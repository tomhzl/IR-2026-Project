# IR 2026 实验报告：基于 BM25 与 TF-IDF 混合检索的证据问答系统

课程：信息检索；数据版本：IR2026-BCP-200-v1；运行协议：ir2026.retrieval.v2。

作者、学号与组员分工：提交前按实际情况填写。报告整理日期：2026 年 11 月 12 日。

## 摘要

本实验面向固定本地语料上的复杂问题检索与证据问答，实现了片段级 BM25 基线，以及全文 TF-IDF 与片段 BM25 的加权倒数排名融合方法。在检索阶段，系统为每道问题返回最多 10 篇文档；在问答阶段，从这些文档选择连续原文片段，调用 SiliconFlow 的 Qwen/Qwen3.5-4B 生成简短答案和证据编号，再将证据编号映射为本地原文引用。

完整验证集共 50 题，BM25 基线的 GoldHit@10 为 24%，当前混合检索为 32%，EvidenceRecall@10 从 9.24% 提升至 21.47%。消融实验同时发现，单独全文 TF-IDF 的验证集 GoldHit@10 为 34%，略高于混合检索，说明训练集上最优的融合权重没有在所有验证指标上保持优势。接入 Qwen 的历史 v1 验证运行作答 24 题，严格答案匹配 7 题，AnswerEM 为 14%。整理代码后采用固定 v1 配置完成测试集 50 题，作答 29 题，提交格式及原文引用检查通过；测试标注未公开，因此不报告测试准确率或检索命中率。

本报告覆盖基础作业及“检索方法改进”选做。未进行小模型后训练，不将模型 API 调用或无监督 LSA 索引构建表述为语言模型后训练。

## 1. 任务、数据与实验边界

### 1.1 任务定义

输入自然语言问题 Q，在固定语料 D 中检索相关文档，输出有序文档 ID、简短答案及支持答案的原文引用。主评价指标为 GoldHit@10，答案严格匹配仅作为辅助指标。普通固定检索流水线采用 `method_type=retrieval`，不要求模型自主调用工具。

### 1.2 数据划分

| 数据 | 数量 | 本实验用途 |
| --- | ---: | --- |
| 训练问题 | 100 | 检索权重选择与离线对照分析 |
| 验证问题 | 50 | 全量评测与失败案例分析 |
| 测试问题 | 50 | 固定配置生成最终结果，等待教师评测 |
| 本地语料 | 10,000 篇 | 三个问题划分共用的检索范围 |

语料正文约 318 MB，包括 1,185 篇已标注证据或答案文档、5,901 篇抽样难负例和 2,914 篇补充文档。课程划分不是 BrowseComp-Plus 官方完整划分，本文结果仅适用于课程数据。

索引仅使用本地语料。融合权重在训练集选择；消融脚本完成排名后才读取标签评分，运行时不读取答案标签。验证集用于报告对照结果。测试问题不用于训练、调参或案例驱动修改。

### 1.3 输出约束

每题最多 600 秒，返回最多 10 篇文档和 5 段引用，每段引用为 20–1200 个 Unicode 字符的连续原文。失败与未作答题均保留。模型自主工具交互的预算为最多 32 次、每次观测最多 12,000 字符；本实现为固定检索流程，没有模型发起的工具调用。日志中的 `mean_tool_calls=0` 不表示没有调用答案生成 API，模型成本另以 Token 和耗时记录。

问题与本地候选片段发送给已授权的模型 API，未使用联网搜索扩展语料。模型仅返回片段编号，由程序从本地正文生成引用，避免直接将模型自由生成的文本当作原文证据。

## 2. 基础系统实现

### 2.1 系统流程与模块

```text
问题 → BM25 多查询召回 ───────┐
                           ├→ 加权 RRF → 前 10 篇文档
问题 → 全文 TF-IDF 召回 ─────┘             ↓
                                 原文片段选择
                                         ↓
                              规则提取 / Qwen 生成
                                         ↓
                              答案、文档 ID、原文证据
```

| 模块 | 实现文件 | 职责 |
| --- | --- | --- |
| 固定入口 | `run_qwen_hybrid.py` | 读取当前 v1 配置并启动运行 |
| 通用运行器 | `run.py` | 逐题执行、时间预算、日志与断点续跑 |
| BM25 | `build_index.py`、`agent/retrieval.py` | 片段索引、多查询召回和文档融合 |
| 混合检索 | `build_hybrid_index.py`、`agent/hybrid.py` | 全文表示、余弦检索和加权融合 |
| 证据定位 | `agent/evidence.py` | 从候选文档选择连续正文窗口 |
| 答案生成 | `agent/answer.py`、`agent/prompts.py` | 模型请求、JSON 解析及版本化提示词 |
| v1 核验 | `agent/answer_policy.py` | 特定编号线索题的布尔核验 |
| 流程组织 | `agent/solution.py` | 串联检索、证据和答案策略 |
| 检查与评分 | `check_results.py`、`evaluate.py` | 格式、引用、日志校验及离线评测 |

### 2.2 片段级 BM25 基线

为缓解长文档中相关内容被大量无关正文稀释的问题，将每篇文档按 1800 字符分片，相邻片段重叠 250 字符，步长为 1550。SQLite FTS5 表存储原文档 ID、片段起点与正文，使用 `porter unicode61` 分词配置；文档 ID 与位置字段不参与正文检索。当前索引包含 208,245 个片段。

查询预处理通过正则提取英文词、缩写和四位年份，过滤停用词并按出现顺序去重。分别取最前 8 个词、最后 8 个词和最长 8 个词，组成最多三条 OR 查询。每条表达式检索 BM25 排名前 100 个片段，再按文档 ID 去重。因此，每条查询保留下来的文档数可能少于 100。

FTS5 默认 `rank` 使用其 BM25 排序函数，较小的数值排在前面。该分数针对当前 MATCH 表达式及片段计算，不直接等于最终文档分数。单条查询内去重后按文档出现顺序赋排名，再进行 RRF：

```text
S_BM25(d) = Σ_q 1 / (30 + rank_q(d))
```

只有在查询 q 中出现的文档参与该项求和。这样，一个文档不会因同一查询命中多个片段而重复累加，但可以因在不同查询中出现而获得多次贡献。按融合分数选取前 10 篇作为基线输出；首次命中的片段作为后续证据定位的候选之一。

### 2.3 证据选择

证据选择不是将整篇文档直接发送给模型。系统对前 10 篇文档执行以下处理：

1. 保留文档开头和 BM25 命中片段，以兼顾实体介绍与正文相关段落。
2. 使用问题末尾 500 字符中的重点词，对候选文档内部再次进行 FTS 查询。
3. 对非首位文档增加问题词在全文中的位置窗口，缓解答案出现在长文档深处的问题。
4. 根据重点词及全问题词覆盖打分，过滤起点距离过近的重复窗口。

排名第一的文档最多保留 6 个、每个最长 1000 字符的片段；其余文档各最多保留 3 个、每个最长 1200 字符的片段。所有片段最终都从本地正文按位置截取。这里的数量是输入模型的候选片段数，最终提交引用仍最多 5 段。

### 2.4 答案生成与 v1 策略

系统先尝试保守的明确百分比规则提取；无法提取时调用 `Qwen/Qwen3.5-4B`，要求返回含 `answer` 与 `evidence_ids` 的 JSON。主提示词要求答案由本地片段支持，允许同主题片段直接给出目标实体或数值，而不要求全部背景线索在同一片段出现。

首轮未作答时，每篇文档取最多两个聚焦片段执行一次回退。回退答案必须字面出现在所选片段中，且引用至少两篇不同文档。只有问题中出现至少三个数字编号线索、且答案由模型生成时，v1 执行原版布尔核验。所有 v1 请求关闭思考，输出上限为 1200 Token。单题可能产生多次 API 请求，实际次数和用量以日志为准。

模型返回的证据编号必须属于输入候选，程序最多保留 5 段原文。不能作答时返回空答案、`no_answer` 和相关原文。原文引用校验只证明文本确实来自语料，不能证明其语义上支持答案；v1 的宽松作答策略也不能保证消除幻觉。

## 3. 检索方法改进

### 3.1 改进动机

片段 BM25 有利于定位局部信息，但查询仅保留有限关键词，可能遗漏复杂问题中的区分性条件；同一文档的多段线索也难以在一个窗口中聚合。为此增加以完整问题为查询的全文 TF-IDF 召回，与片段级局部匹配形成互补。同时实现 LSA 作为对照，检验语料内低维表示是否有帮助。

### 3.2 全文 TF-IDF

在全部 10,000 篇原始文档上拟合 TF-IDF，采用小写化、Unicode 重音规范化、英文停用词过滤，以及 unigram 和 bigram 特征。最大词表为 120,000，`min_df=2`、`max_df=0.95`，启用次线性词频和 L2 归一化，使用 float32 存储。查询不裁剪为三组短词，而是对完整问题进行相同变换。

文档和查询均已归一化，因此稀疏向量点积等于余弦相似度：

```text
S_TFIDF(q,d) = x_q · x_d
```

每路最多返回 100 篇正分候选。全文表示有助于综合分散线索，但仍依赖词面重合，不能等同于神经语义检索。

### 3.3 LSA 消融分支

对 TF-IDF 矩阵进行 192 维 TruncatedSVD，迭代次数为 5，随机种子为 2026。归一化低维文档向量，并将查询投影至同一空间，以余弦相似度排序。索引的解释方差比例约为 16.60%。

LSA 仅在本地语料上无监督拟合，未训练语言模型、未使用预训练神经 embedding。低维压缩可能捕获词的共现主题，也可能丢失人名、时间和数值等细粒度区分信息。

### 3.4 加权 RRF 与参数选择

各路原始分数尺度不同，因此以排名融合：

```text
S_hybrid(d) = Σ_m w_m / (30 + rank_m(d))
```

其中 m 表示 BM25、TF-IDF 或 LSA；未召回的文档在该路贡献为 0。BM25 路输入是先经多查询 RRF 得到的文档排名，最终融合只使用其位置，不将内部 RRF 分数当作另一种相似度直接相加。

训练集固定 TF-IDF 权重为 1，枚举 BM25 权重 {0.5, 1, 2} 和 LSA 权重 {0, 0.25, 0.5, 1}，共 12 组。优先按训练集 GoldHit@10，随后按 EvidenceRecall@10、Hit@5 和较小 LSA 权重选择配置。最终固定：

| 参数 | 取值 |
| --- | --- |
| BM25 权重 | 0.5 |
| TF-IDF 权重 | 1.0 |
| LSA 权重 | 0.0 |
| RRF 常数 | 30 |
| 每路候选上限 | 100 篇 |
| 最终返回上限 | 10 篇 |

LSA 权重为 0 时，正式流水线不加载或执行该分支。当前配置冻结在 `configs/qwen_hybrid_v1.json`；权重搜索更新的是独立的 `configs/hybrid.json`，不会修改已冻结方案。

## 4. 实验设置与评价指标

### 4.1 实验环境与版本

报告整理时的环境为 Python 3.13.11、SQLite 3.51.0；依赖固定为 NumPy 2.4.6、SciPy 1.18.0、scikit-learn 1.9.0 和 threadpoolctl 3.6.0。检索与索引构建使用 CPU，答案生成通过远端 API。未单独测量峰值内存，因此不报告峰值内存指标。

索引通过语料清单 SHA256 校验一致性，使用临时文件构建并原子替换。TF-IDF/LSA 索引不采用 pickle 加载。

### 4.2 指标定义

- **GoldHit@k**：前 k 篇与该题 `gold_doc_ids` 有交集记为 1，再在全部问题上平均；报告 k=1、5、10。
- **EvidenceRecall@10**：前 10 篇覆盖的标注证据文档数除以该题标注证据文档总数，再对问题平均。它不是提交引用段落的召回率。
- **AnswerEM**：使用项目的保守规范化严格匹配；不是人工语义正确率，也不计入自动效果分。
- **作答率**：非空答案或 `status=ok` 的题目比例，不代表正确率。
- **成本与可复现性**：逐题耗时、API Token、日志完整性、引用来源及结果格式检查。

基础作业中自动效果分的 6 分按 `6 × GoldHit@10` 计算，另 2 分由全量提交、格式、引用和日志一致性检查。本文验证分数仅用于实验分析，不能视为教师最终测试成绩。

### 4.3 运行记录的范围

检索对照使用已经保存的全量 train/dev 排名和指标。Qwen 的 dev 数据来自历史 `siliconflow_qwen35_hybrid_dev_v1` 运行；test 来自代码整理后的固定 v1 入口。二者采用同一选定策略，但不是代码整理后重新运行的一次统一实验。API 服务与模型输出可能波动，报告保留实际历史结果，不用新文件名覆盖旧结果。

## 5. 实验结果

### 5.1 基础检索与改进方法的完整验证结果

| 方法 | Hit@1 | Hit@5 | Hit@10 | EvidenceRecall@10 |
| --- | ---: | ---: | ---: | ---: |
| 片段 BM25 多查询 RRF | 6% | 20% | 24% | 9.24% |
| 全文 TF-IDF | 12% | 22% | **34%** | 20.55% |
| 全文 LSA，192 维 | 12% | 22% | 30% | 14.71% |
| 当前 BM25 + TF-IDF 混合检索 | **14%** | **24%** | 32% | **21.47%** |

混合检索相对 BM25 的 Hit@10 增加 8 个百分点，即多命中 4 题；相对提升约 33.3%。EvidenceRecall@10 增加 12.23 个百分点，说明在现有标注下覆盖了更多证据文档。按验证 Hit@10 换算，效果项从 1.44/6 增至 1.92/6，不能直接替代最终测试得分。

全文 TF-IDF 的 Hit@10 为 34%，比当前混合检索高 2 个百分点，仅差 1 题；混合方法的 Hit@1、Hit@5 和证据召回更高。不能据此宣称混合方法在所有指标上最优。验证集仅 50 题，单题就对应 Hit 指标的 2 个百分点，本文没有进行统计显著性检验。

### 5.2 训练集对照与权重消融

| 方法 | Train Hit@10 | Train EvidenceRecall@10 |
| --- | ---: | ---: |
| BM25 | 25% | 10.81% |
| TF-IDF | 39% | 20.14% |
| LSA | 21% | 11.77% |
| 选定混合检索 | **45%** | **21.83%** |

训练集完整 12 组融合实验如下，TF-IDF 权重始终为 1：

| BM25 权重 | LSA 权重 | Train Hit@10 |
| ---: | ---: | ---: |
| 0.5 | 0 | **45%** |
| 0.5 | 0.25 | 44% |
| 0.5 | 0.5 | 43% |
| 0.5 | 1 | 39% |
| 1 | 0 | 41% |
| 1 | 0.25 | 41% |
| 1 | 0.5 | 42% |
| 1 | 1 | 38% |
| 2 | 0 | 34% |
| 2 | 0.25 | 34% |
| 2 | 0.5 | 35% |
| 2 | 1 | 37% |

在当前搜索范围内，较低 BM25 权重更有利，说明全文词项匹配对本数据提供了较强信号。LSA 权重为 0 的组合取得最高训练 Hit@10；加入 LSA 没有稳定收益，因而正式配置关闭该分支。上述分析只适用于已测试权重范围，不能证明所有潜在语义检索方法都无效。

训练集混合检索优于单路 TF-IDF，而验证集排序相反，提示融合参数存在泛化限制。可能原因包括问题分布差异、BM25 局部主题匹配引入干扰，以及仅使用全局固定权重；这些是解释假设，尚未通过额外受控实验确认。

### 5.3 答案生成结果

| 配置 | Dev Hit@10 | 作答数 | 严格匹配数 | AnswerEM |
| --- | ---: | ---: | ---: | ---: |
| 混合检索，不生成答案 | 32% | 0/50 | 0/50 | 0% |
| Qwen + 混合检索 v1 | 32% | 24/50 | 7/50 | 14% |

两组检索命中率一致，说明增加答案生成没有改变文档排序；模型输出不能弥补召回文档中缺失的答案证据。无答案生成组是检索对照，0% AnswerEM 是其设计结果，不能解释为检索无效。

v1 的 24 个答案中，严格匹配比例为 7/24，约 29.17%，但不能把其余全部认定为语义错误，因为存在输出顺序等格式差异。未命中 gold 的题也不必然语义无解，标注可能未穷尽相关文档，仍需检查实际引用。

### 5.4 索引与运行成本

| 项目 | 实测值 |
| --- | ---: |
| FTS5 索引片段数 | 208,245 |
| FTS5 索引大小 | 652,144,640 字节，约 621.9 MiB |
| TF-IDF/LSA 合并索引大小 | 150,901,650 字节，约 143.9 MiB |

## 6. 成功与失败案例

以下案例全部来自固定的 dev v1 结果，标签仅用于事后分析，没有参与检索或生成。

### 6.1 成功：628，电影名称识别

问题要求识别 2017 年、19 分钟、导演学过公共行政的短片。返回首位文档为 4965，标题为 Brazuca；引用包含制作年份、片长、导演及公共行政学习经历。模型输出 `Brazuca`，与标签一致，且前 10 篇覆盖多篇 gold 文档。

该例中关键实体和多条区分线索集中在同一介绍页，全文召回与片段选择能够向模型提供直接证据，降低了跨文档关系推导的难度。

### 6.2 成功：769，大学名称识别

问题用毕业典礼、活动和地理位置等多条历史线索定位大学。系统在第 3 位返回 gold 文档 82002，其标题及正文直接出现 `Queen Arwa University`，正文记载 2003 年 6 月 22 日星期日的毕业典礼。模型输出该校名，与标签一致。

该例说明目标文档不必排名第一也能支持作答；向前 10 篇文档分配证据窗口有实际价值。不过正确答案不等于程序已逐一验证问题的全部背景条件。

### 6.3 失败：761，命中文档但没有输出答案

问题询问财政年度非 GAAP 运营费用下降比例，标签答案为 `7%`。系统在第 6 位命中 gold 文档 12217，也返回证据文档 72685，但输出空答案。已提交引用涉及运营收益率和后续财务表格，未直接给出目标费用变化的答案。

这个例子表明“命中 gold 文档”和“提供正确答案窗口”是两个阶段。长年报包含多个相近年份、指标和百分比，词项覆盖窗口容易混入相关但不回答问题的段落。仅靠该输出还不能唯一判断是全部候选窗口遗漏了答案，还是模型未能利用已有窗口；需要检查该题 `read_evidence_candidates` 和生成日志进一步定位。

### 6.4 失败：324，命中 gold 但答案类型错误

问题最后询问某扑克赛事更早一届的获胜者。系统在第 2 位命中 gold 文档 42885，模型却输出年份 `2008`，标签为人物 `Svetlana Gromenkova`。该文档引用确实包含赛事及人物信息，但输出没有回答“谁获胜”。

这是答案生成阶段的目标属性错误，不能简单归因为检索未命中。改进应优先检查最终问句所需类型和关系，而非只提高文档相关性。v1 对多数问题未执行独立语义核验，因此保留了这类错误。

### 6.5 失败：471，目标关系的证据未召回

问题要求论文作者当时丈夫的姓名，标签为 `Scott A. Ebers`。系统召回了作者获奖等背景文档，但未召回 gold 文档 12516，最终输出作者本人 `Valerie Martinez-Ebers`。引用能支持作者获奖，不能支持其丈夫是谁。

这里同时存在召回缺失和关系混淆：关键词可定位作者，却未必能定位论文致谢部分。后续可研究依据已确认实体开展第二阶段检索，但本报告没有将未实施的多跳方案记为实验成果。

### 6.6 评价差异：478，答案信息相同但顺序不同

模型输出 `December 6, 2019; Eldorado Stadium`，标签为 `Eldorado Stadium; December 6, 2019`，前 10 篇包含两篇 gold 文档。输出涵盖同一日期和场馆，但项目严格匹配将其计为未匹配。

这说明 AnswerEM 与语义正确性存在差异。报告保留官方脚本给出的 14%，不私自调整标签或评分；案例分析单独说明格式因素，不将该结果计入正式严格匹配成功数。

## 7. 复现与交付说明

### 7.1 环境、数据与索引

在项目根目录执行，当前方案与完整测试建议使用 Python 3.12+：

```bash
python3 -m pip install -r requirements.txt
python3 verify_data.py --full
python3 build_index.py
python3 build_hybrid_index.py

```

已有且语料指纹一致的索引可以复用。`SILICONFLOW_API_KEY` 配置在环境变量或项目 `.env` 中，格式见 `.env.example`。不将密钥写入报告或提交包。

### 7.2 复现检索对照

下面的命令使用新输出目录，避免覆盖原始实验。训练集权重搜索会更新 `configs/hybrid.json`：

```bash
python3 benchmark_hybrid.py --split train --select-config \
  --output output/report_train_ablation
python3 benchmark_hybrid.py --split dev \
  --output output/report_dev_ablation

python3 run.py --split dev --agent agent.solution --retriever bm25 \
  --retrieval-only --method-label report-bm25 \
  --output output/report_bm25_dev
python3 check_results.py --split dev --run-dir output/report_bm25_dev --submission
python3 evaluate.py --split dev --run-dir output/report_bm25_dev

python3 run.py --split dev --agent agent.solution --retriever hybrid \
  --hybrid-config configs/qwen_hybrid_v1.json --retrieval-only \
  --method-label report-hybrid --output output/report_hybrid_dev
python3 check_results.py --split dev --run-dir output/report_hybrid_dev --submission
python3 evaluate.py --split dev --run-dir output/report_hybrid_dev
```

消融脚本保存逐题候选排名与各方法指标；通用运行器保存正式格式结果和日志。不要将消融摘要直接替代完整提交目录。

### 7.3 复现答案生成与测试输出

```bash
python3 run_qwen_hybrid.py --show-config
python3 run_qwen_hybrid.py --split dev --output output/report_qwen_dev
python3 check_results.py --split dev --run-dir output/report_qwen_dev --submission
python3 evaluate.py --split dev --run-dir output/report_qwen_dev

# 已完成的测试集只需检查；不要为调参反复使用测试反馈。
python3 check_results.py --split test --run-dir output/qwen_hybrid_v1_test --submission
```

首次从零生成测试结果的命令为 `python3 run_qwen_hybrid.py --split test`；已存在同配置的未完成运行可添加 `--resume`。恢复时核对问题、模型、权重和答案策略，复用成功及未作答记录，重跑失败题。输出目录应为新目录或符合续跑要求，不混用不同实验结果。重新调用远端模型不保证答案逐字复现。

## 8. 局限与后续研究

本系统仍以词面匹配为主，对跨文档实体关系、间接表述和多步推导支持有限。片段选择依据关键词覆盖，无法确保覆盖全部必要证据；Qwen v1 的宽松策略提高作答量，但存在关系错误和类型错误。加入更严格核验也可能误拒正确答案，因此不能只用作答数评估质量。

检索改进的实际贡献是全文与片段两种粒度互补、可复现的排名融合，以及包含无收益分支的消融分析。当前全局权重在训练与验证集上的最优性不同，没有证据支持其为通用最优方案。后续可在 train/dev 上研究候选重排序、查询线索拆解和更精确的证据窗口选择，并分别报告检索、定位、生成各阶段的效果与成本。上述方案尚未实施，不计入本次成果；测试集不参与后续开发。
